# 🧠 Руководство пользователя системы памяти NPC

## 📚 Обзор

У NPC в Кибер-городе теперь есть **система памяти**, которая может запоминать историю разговоров с игроками и цитировать предыдущий контент в последующих разговорах, что делает NPC более умными и реальными!

---

## ✨ Основные функции

### 1. **Рабочая память** — кратковременная память.
- 📝 Сохраните последние 10 разговоров
- ⏰ Автоматически истекает через 2 часа.
- 🚀 Быстрый поиск текущего контекста разговора

### 2. **Эпизодическая память** – долговременная память.
- 💾 Постоянное хранение важных разговоров
- 🔍 Поддерживает семантический поиск (на основе векторной базы данных Qdrant)
- 📊 Храните до 100 воспоминаний
- 🧹 Автоматически забывать воспоминания, важность которых ниже 0,3.

### 3. **Изоляция памяти**
- 🔒 Каждый NPC имеет независимую систему памяти.
- 🚫 Воспоминания между NPC не будут мешать друг другу
- 👤 Диалоги каждого игрока сохраняются независимо

## 🔧 Техническая реализация

### Архитектурный дизайн

```
NPCAgentManager
├── agents: Dict[str, SimpleAgent]          # NPC Agent
├── memories: Dict[str, MemoryManager]      # Менеджер памяти NPC
└── chat(npc_name, message, player_id)      # Диалоговый интерфейс
    ├── 1. Получите соответствующие воспоминания
    ├── 2. Создавайте расширенные слова-подсказки
    ├── 3. Позвоните агенту, чтобы получить ответ
    └── 4. Сохранить разговор в памяти
```

### Структура хранения памяти

```
backend/memory_data/
├── Чжан Сан/
│   ├── sqlite_store.db          # База данных SQLite (авторитетное хранилище)
│   └── qdrant_collection/       # Индекс вектора Qdrant (семантический поиск)
├── Ли Си/
│   ├── sqlite_store.db
│   └── qdrant_collection/
└── Ван Ву/
    ├── sqlite_store.db
    └── qdrant_collection/
```

### Формат данных памяти

```python
{
    "id": "memory_uuid",
    "content": "Игрок сказал: Привет, чем занимаешься?",
    "type": "working",  # working/episodic
    "importance": 0.5,  # между 0-1
    "timestamp": "2024-01-15T10:30:00",
    "metadata": {
        "speaker": "player",
        "player_id": "player",
        "session_id": "player",
        "context": {
            "interaction_type": "dialogue",
            "npc_name": "Чжан Сан"
        }
    }
}
```

## 📊 Конфигурация системы памяти

### Параметры конфигурации (агенты.py)

```python
memory_config = MemoryConfig(
    storage_path=f"./memory_data/{npc_name}",  # путь хранения
    working_memory_capacity=10,                # объем рабочей памяти
    working_memory_tokens=2000,                # Ограничение токена рабочей памяти
    max_capacity=100,                          # общий объем памяти
    importance_threshold=0.3,                  # порог важности
    decay_factor=0.95                          # коэффициент затухания во времени
)
```

### Рекомендации по настройке

| Параметры | Значение по умолчанию | Рекомендуемый диапазон | Описание |
|------|--------|----------|------|
| объем рабочей_памяти | 10 | 5-20 | Объем рабочей памяти, чем она больше, тем больше памяти она занимает |
| токены рабочей_памяти | 2000 | 1000-4000 | Предел токена, влияющий на длину контекста |
| максимальная_емкость | 100 | 50-500 | Общий объем памяти, чем он больше, тем больше места на диске занимает |
| значение_порога | 0,3 | 0,1-0,5 | Порог важности: чем выше значение, тем больше важных воспоминаний сохраняется |
| фактор распада | 0,95 | 0,8-0,99 | Коэффициент временного затухания: чем он ниже, тем больше внимания уделяется недавним воспоминаниям |

## 🎓 Ценность обучения

### Очки обучения

1. **Использование MemoryManager**
   - Как инициализировать диспетчер памяти
   - Как настроить разные типы памяти
   - Как добавлять и извлекать воспоминания

2. **Стратегии восстановления памяти**
   - Рабочая память: быстрое восстановление последних разговоров.
   - Эпизодическая память: история, связанная с семантическим поиском.
   - Гибридный поиск: объедините время и релевантность

3. **Механизм хранения памяти**
   - SQLite: авторитетное хранилище данных
   - Qdrant: векторный семантический поиск
   -Двойное хранилище обеспечивает согласованность данных

4. **Механизм забывания памяти**
   - Автоматическое забывание в зависимости от важности
   - Срок действия TTL по времени
   - Приоритетное устранение ограничений мощности

## ❓ Часто задаваемые вопросы

### Q1: Почему NPC не может запомнить диалог?

**Возможные причины:**
- Система памяти инициализирована неправильно.
- Проблема с разрешением пути хранения.
- Воспоминания очищаются механизмом забывания

**Решение:**
- Проверьте, есть ли в журнале «инициализация системы памяти»
- Проверьте, существует ли каталог Memory_data.
- Уменьшить параметр важности_порога.

### В2: Восстановление памяти неточно?

**Возможные причины:**
- Сходство между оператором запроса и содержимым памяти низкое.
- Важность памяти слишком низкая и фильтруется

**Решение:**
- Уменьшить параметр min_importance
- Увеличение количества ограничений поиска
- Используйте более конкретные операторы запроса.

### В3: Память занимает слишком много места?

**Решение:**
- Уменьшить максимальную емкость
- Увеличение важности_порога
- Регулярно очищайте старые воспоминания
