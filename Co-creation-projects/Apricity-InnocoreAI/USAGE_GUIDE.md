# Руководство по использованию InnoCore AI

## Быстрый старт

### 1. Запуск сервера

```bash
python run.py
```

Сервер запустится по адресу `http://localhost:8000`.

### 2. Открытие интерфейса

В браузере откройте:
- **Главная**: http://localhost:8000
- **Документация API**: http://localhost:8000/docs
- **Проверка работоспособности**: http://localhost:8000/health

### 3. Проверка системы

Запустите скрипт проверки, чтобы убедиться, что всё работает:

```bash
python verify_system.py
```

## Режимы работы

InnoCore AI поддерживает два режима:

### 🔹 Индивидуальный режим (Individual Mode)
Независимое использование каждого агента. Подходит для:
- одиночных задач;
- точного контроля каждого шага;
- быстрого тестирования функций.

### 🔹 Координируемый режим (Workflow Mode) ⭐ Рекомендуется
Автоматическая координация всех агентов для полного рабочего процесса. Подходит для:
- полного исследовательского цикла;
- автоматизированной пакетной обработки;
- генерации сводных отчётов.

**Полный рабочий процесс**:
1. Hunter ищет релевантные статьи
2. Miner глубоко анализирует каждую статью
3. Validator формирует стандартные цитаты
4. Coach пишет сводный отчёт

## Использование функций

### 📚 Hunter — поиск статей

**Функция**: поиск академических статей на ArXiv.

**Как использовать**:
1. В карточке «Hunter — поиск статей» введите ключевые слова
2. Выберите источник данных (по умолчанию ArXiv)
3. Укажите количество результатов (1–50)
4. Нажмите «Начать поиск»

**Примеры ключевых слов**:
- `machine learning`
- `deep learning`
- `natural language processing`
- `computer vision`

**Возвращаемая информация**:
- заголовок статьи;
- список авторов;
- аннотация;
- дата публикации;
- ArXiv ID;
- ссылка на PDF.

### 🔍 Miner — анализ статей

**Функция**: глубокий анализ содержания статьи с полным разбором PDF.

**Как использовать**:
1. **Способ 1: ArXiv URL**
   - Введите URL ArXiv (например, `https://arxiv.org/abs/2301.00001`)
   - Система автоматически получит информацию о статье

2. **Способ 2: загрузка PDF**
   - Нажмите или перетащите PDF-файл
   - Система автоматически разберёт и извлечёт:
     * заголовок;
     * авторов;
     * аннотацию;
     * полный текст;
     * число страниц и слов.
   - После разбора поле URL заполнится автоматически

3. Выберите тип анализа:
   - **summary (аннотация)**: краткое изложение статьи
   - **innovation (инновации)**: анализ технических новшеств
   - **comparison (сравнение)**: сравнение с существующими методами
   - **comprehensive (комплексный)**: полный глубокий анализ

4. Нажмите «Начать анализ»

**Поддерживаемые форматы ввода**:
- ArXiv URL: `https://arxiv.org/abs/XXXX.XXXXX`
- ArXiv ID: `2301.00001`
- PDF-файл: любой стандартный PDF (рекомендуется текстовая версия)

**Возможности разбора PDF**:
- ✅ автоматическое извлечение заголовка и авторов
- ✅ интеллектуальное определение раздела аннотации
- ✅ извлечение полного текста
- ✅ подсчёт страниц и слов
- ✅ AI-анализ на основе полного содержания

**Примечания**:
- у отсканированных PDF текст может не извлекаться;
- для лучшего результата используйте текстовые PDF;
- рекомендуемый размер файла — не более 50 МБ.

### ✍️ Coach — помощник по письму

**Функция**: помощь в академическом письме.

**Как использовать**:
1. Введите текст в поле ввода
2. Выберите стиль:
   - **академический**: формальный научный стиль
   - **технический**: стиль технической документации
   - **популярный**: доступный научно-популярный стиль
3. Выберите тип задачи:
   - **улучшение**: повышение качества текста
   - **редактура**: оптимизация формулировок
   - **перевод**: многоязычный перевод
   - **проверка**: грамматика и орфография
4. Нажмите «Начать обработку»

**Сценарии применения**:
- редактура аннотации статьи;
- улучшение технической документации;
- академический перевод;
- проверка грамматики.

### ✅ Validator — проверка цитирования

**Функция**: форматирование и проверка академических ссылок.

**Как использовать**:
1. Введите данные цитирования (поддерживаются разные форматы)
2. Выберите целевой формат:
   - **BibTeX**: для документов LaTeX
   - **APA**: формат Американской психологической ассоциации
   - **IEEE**: формат Института инженеров электротехники и электроники
   - **MLA**: формат Совета современных языков
3. Нажмите «Начать проверку»

**Поддерживаемый ввод**:
- ссылки с DOI;
- ArXiv URL или ID;
- текст ссылки в свободной форме.

**Автоматическое распознавание**:
- проверка DOI через Crossref API;
- извлечение ArXiv ID;
- AI-парсинг данных цитирования.

### 🔄 Полный рабочий процесс (рекомендуется)

**Функция**: одним действием пройти путь от поиска до отчёта.

**Как использовать**:
1. Переключитесь в «координируемый режим»
2. Введите ключевые слова исследования
3. Выберите количество статей (3/5/10)
4. Выберите тип анализа
5. Выберите формат цитирования
6. Отметьте «Сгенерировать сводный отчёт» (опционально)
7. Нажмите «Запустить полный рабочий процесс»

**Автоматические шаги**:
- ✅ Шаг 1: поиск релевантных статей
- ✅ Шаг 2: анализ первых 3 статей
- ✅ Шаг 3: генерация стандартных цитат
- ✅ Шаг 4: написание сводного отчёта (опционально)

**Преимущества**:
- экономия времени — всё в один клик;
- автоматическая координация без ручного переключения;
- объединённые результаты для удобного просмотра;
- подходит для массовых исследований.

## Использование API

### API поиска статей

```bash
curl -X POST "http://localhost:8000/api/v1/papers/search" \
  -H "Content-Type: application/json" \
  -d '{
    "keywords": "machine learning",
    "source": "arxiv",
    "limit": 10
  }'
```

### API анализа статей

```bash
curl -X POST "http://localhost:8000/api/v1/analysis/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "paper_url": "https://arxiv.org/abs/2301.00001",
    "analysis_type": "summary"
  }'
```

### API помощника по письму

```bash
curl -X POST "http://localhost:8000/api/v1/writing/coach" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Your text here",
    "style": "academic",
    "task": "improve"
  }'
```

### API проверки цитирования

```bash
curl -X POST "http://localhost:8000/api/v1/citations/validate" \
  -H "Content-Type: application/json" \
  -d '{
    "citation": "Your citation here",
    "format": "bibtex"
  }'
```

### API полного рабочего процесса

```bash
curl -X POST "http://localhost:8000/api/v1/workflow/complete" \
  -H "Content-Type: application/json" \
  -d '{
    "keywords": "deep learning",
    "limit": 5,
    "analysis_type": "summary",
    "citation_format": "bibtex",
    "writing_task": "improve"
  }'
```

### API упрощённого рабочего процесса (только поиск + анализ)

```bash
curl -X POST "http://localhost:8000/api/v1/workflow/search-and-analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "keywords": "machine learning",
    "limit": 3,
    "analysis_type": "summary"
  }'
```

## Частые вопросы

### В: Поиск статей не даёт результатов?
О: Попробуйте более общие ключевые слова или проверьте сетевое подключение к ArXiv.

### В: Анализ статьи не удался?
О: Убедитесь, что указан корректный ArXiv URL или ID, например `https://arxiv.org/abs/2301.00001`.

### В: Помощник по письму отвечает медленно?
О: Обработка LLM занимает время — подождите. В `.env` можно настроить более быструю модель.

### В: Проверка цитирования не проходит?
О: Укажите ссылку с DOI или ArXiv URL — тогда проверка выполнится автоматически.

## Конфигурация

### Переменные окружения

В файле `.env`:

```env
# Конфигурация AI-модели
LLM_API_KEY=your_api_key
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_NAME=gpt-3.5-turbo

# Конфигурация БД (опционально)
DATABASE_URL=postgresql://user:password@localhost:5432/innocore

# Конфигурация векторной БД (опционально)
QDRANT_HOST=localhost
QDRANT_PORT=6333
```

### Выбор модели

Поддерживаемые модели:
- OpenAI: `gpt-3.5-turbo`, `gpt-4`
- ModelScope: через настройку `base_url`
- другие модели, совместимые с OpenAI API
