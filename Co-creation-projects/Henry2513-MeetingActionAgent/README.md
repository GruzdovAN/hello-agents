# MeetingActionAgent

> Два агента HelloAgents превращают стенограмму совещания в прослеживаемые и исполнимые протоколы.

## О проекте

Небольшой продуктивный проект с двумя агентами. На входе — текст протокола на китайском; далее:

1. `MinutesAgent` извлекает дату, резюме, решения, action items и открытые вопросы.
2. `ReviewAgent` сверяет черновик с оригиналом: пропуски, выдумки, конфликты дат.
3. При неуспехе ревью — одна итерация исправления.
4. Итог: структурированный JSON и читаемый Markdown.

Правило v1: не додумывать то, чего нет в тексте. Неизвестный ответственный или дата — «не указано».

## Основные возможности

- Два агента последовательно: извлечение и проверка
- Валидация Pydantic: пропущенные поля и типы
- Ограниченные повторы: до четырёх вызовов модели
- Доказательства: для каждого action item — цитата из оригинала

## Рабочий процесс

```text
Стенограмма
  → MinutesAgent: структурированный черновик
  → ReviewAgent: сверка с оригиналом
  → при необходимости одно исправление и повтор ревью
  → JSON и Markdown
```

## Быстрый старт

### Требования

- Python 3.11+
- OpenAI-compatible LLM API

### 1. Окружение

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 2. Модель

Скопируйте `.env.example` в `.env`:

```dotenv
LLM_MODEL_ID=your-model-id
LLM_API_KEY=your-api-key
LLM_BASE_URL=https://your-provider.example/v1
```

`.env` в `.gitignore` — не коммитьте ключи.

### 3. Notebook

```powershell
jupyter lab
```

Откройте `main.ipynb`, ядро — `.venv` проекта, выполните сверху вниз.

Notebook вызывает реальную модель для `data/sample_meeting.txt`.
Запускайте Jupyter из каталога `Henry2513-MeetingActionAgent`; другие рабочие каталоги не поддерживаются.

## Вход и выход

Вход по умолчанию — UTF-8 `.txt`; в Notebook можно вставить текст напрямую.

Выход:

- JSON `MeetingResult`: дата, резюме, решения, action items, открытые вопросы
- Markdown-протокол для людей
- Статус ревью: `passed` или `needs_manual_review`

## Примеры и тесты

- `data/sample_meeting.txt`: обычное совещание с явными задачами и ответственными.
- `data/edge_case_meeting.txt`: размытые формулировки, конфликт дат, нет ответственного.
- Самопроверки Notebook: JSON в fence, опциональные поля, пустые action items, пустой ввод, неверный приоритет.
- `outputs/` — пример успешного прогона для формата.

## Сильные стороны

- Извлечение и ревью разделены; ReviewAgent сверяет с оригиналом построчно.
- Доказательства для каждого action item.
- Не более четырёх вызовов модели и одно исправление после ревью.

## Оценка

Небольшая проверка процесса, без масштабного бенчмарка. Перед сдачей — реальный прогон на `data/sample_meeting.txt`:

- 2 вызова модели, ревью `passed`.
- 4 action items, 1 подтверждённое решение.
- Цитаты для всех 4 action items есть в оригинале.
- 6 офлайн-самопроверок Notebook прошли.

Время ответа зависит от модели и API — фиксированные цифры не приводятся.

## Ограничения

- Только текст; без аудио и live-совещаний.
- Без интернета, БД, RAG, MCP и долгой памяти.
- Вывод LLM недетерминирован; при `needs_manual_review` нужна ручная проверка.
- Примеры вымышленные — не вводите конфиденциальные данные.
