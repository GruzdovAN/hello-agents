# Документ проектирования агента SoftwareDevHelper

## 1. Обзор агента

**Название**: SoftwareDevHelper  
**Роль**: профессиональный помощник в обучении разработке ПО  
**Цель**: предоставлять начинающим разработчикам персонализированный опыт обучения, включая оценку уровня, интеллектуальную генерацию задач, сопровождение в разработке, а также автоматическое тестирование и оценку кода.  
**Основной фреймворк**: построен на парадигме `SimpleAgent` фреймворка `HelloAgents`.

## 2. Системный промпт (System Prompt)

Поведение и обязанности агента строго определяются следующим системным промптом:

```text
你是一个专业的软件开发学习助手。你的职责是：
1. 使用 user_memory 工具了解用户的当前编程水平和历史做题记录。
2. 根据用户水平，为他们出适合的编程题目，或者从网上搜索真实的开发案例。
3. 在用户开发过程中，提供有针对性的建议和指导。
4. 当用户完成开发并上传项目压缩包后，你需要：
   - 仔细分析题目要求。
   - 编写严谨的 pytest 测试用例代码。
   - 使用 code_test 工具，传入压缩包路径和你的测试代码，对用户的项目进行自动化测试。
   - 根据测试结果给出最终打分和详细的代码审查反馈。
5. 任务完成后，使用 user_memory 工具更新用户的水平评估和做题记录。

请始终保持鼓励和专业的态度。
```

## 3. Инструменты и навыки (Tools & Skills)

Агент использует два основных пользовательских инструмента для взаимодействия с внешней средой (файловая система, тестовое окружение, хранилище памяти):

### 3.1 UserMemoryTool (инструмент памяти пользователя)
- **Функция**: управление уровнем программирования пользователя и историей выполненных задач. Обеспечивает персонализированную память между сессиями.
- **Параметры**:
  - `action` (string, обязательный): тип операции — `'get'` (чтение памяти) или `'update'` (обновление памяти).
  - `level` (string, необязательный): новая оценка уровня пользователя (например, `'beginner'`, `'intermediate'`, `'advanced'`).
  - `record` (string, необязательный): запись о выполненной задаче.
- **Реализация**: данные сохраняются в файле `data/user_memory.json` на бэкенде.

### 3.2 CodeTestTool (инструмент автоматического тестирования кода)
- **Функция**: принимает загруженный архив проекта пользователя, автоматически распаковывает его, запускает динамически сгенерированный LLM тестовый код и выставляет оценку.
- **Параметры**:
  - `zip_path` (string, обязательный): абсолютный путь к архиву проекта пользователя.
  - `test_code` (string, обязательный): код тестов `pytest`, динамически сгенерированный агентом по требованиям задачи.
- **Реализация**:
  1. Очистка и создание каталога распаковки `outputs/extracted`.
  2. Распаковка кода пользователя с помощью `zipfile`.
  3. Запись `test_code` в `test_generated.py`.
  4. Вызов `pytest` через `subprocess` с захватом stdout и stderr.
  5. По коду возврата (`returncode`) выставляется 100 баллов (все тесты прошли) или 0 баллов (есть ошибки); подробные логи тестов возвращаются агенту для анализа.

## 4. Сценарий взаимодействия (Workflow)

1. **Инициализация / диалог**: пользователь входит в систему, агент через `UserMemoryTool` получает текущий уровень (например, beginner) и историю.
2. **Этап выдачи задачи**: агент генерирует задачу по программированию подходящей сложности на основе данных из памяти.
3. **Разработка и сопровождение**: пользователь разрабатывает локально и может задавать вопросы в чате; агент даёт рекомендации по коду.
4. **Отправка и тестирование**:
   - Пользователь загружает проект в формате `.zip` через фронтенд.
   - Бэкенд сохраняет файл и передаёт путь агенту в виде системного сообщения.
   - Агент пишет соответствующие тест-кейсы `pytest` (с поддержкой динамического импорта модулей из подкаталогов).
   - Агент вызывает `CodeTestTool` для автоматического тестирования.
5. **Обратная связь и обновление**:
   - Агент выставляет оценку и формирует отчёт по ревью кода на основе логов тестов.
   - Агент вызывает `UserMemoryTool` для записи задачи в историю и при необходимости повышает уровень пользователя.

## 5. Дизайн взаимодействия (Interaction Design)

- **Формат ввода и вывода**:
  - Ввод пользователя: текст на естественном языке, фрагменты кода, архив проекта (.zip).
  - Вывод агента: форматированный Markdown, визуальные элементы вызова инструментов (параметры и результаты в реальном времени).
- **Пользовательский интерфейс (UI)**:
  - Веб-чат с понятным потоком диалога.
  - Поддержка нескольких сессий: боковая панель со списком истории, переключение и удаление.
  - Правая панель показывает текущий уровень пользователя и историю задач.
  - В пузырьках чата — специальные UI-элементы для наглядного отображения вызовов инструментов.
- **Механизм обратной связи**:
  - После оценки — подробный отчёт по ревью кода с сильными сторонами и зонами улучшения.
  - При падении тестов — явное указание: ошибка логики или структуры проекта, с рекомендациями по исправлению.
  - Перед вызовом инструмента агент объясняет предстоящее действие для прозрачности.

## 6. Конфигурация

- **Конфигурация модели**: по умолчанию используется LLM из `.env` (например, `Qwen/Qwen2.5-72B-Instruct`, `Gemini` или `Azure OpenAI`).
- **Особая настройка**: для совместимости с моделями со строгой проверкой JSON Schema (Azure/Gemini) при инициализации `SimpleAgent` через `Config(todowrite_enabled=False)` отключён встроенный инструмент `TodoWrite` фреймворка.
